# QuickPane 3.13.0.1 (fork)

QuickPane 3.13.0.1 changes how QuickPane's own pickers show your pins. If you already run 3.13.0.0, you can update whenever suits you.

## Changed

**Pins inside QuickPane's own pickers ([#231](https://github.com/prisant-labs/windows-explorer-quickpane/issues/231)).** QuickPane opens its own file and folder pickers for Browse in "Edit path", Add folder, Add file, the groups folder, Back up, Restore, and the SSH key. Each of them now lists your pins in its navigation pane, under a QuickPane heading, the way Windows lists Quick Access. They no longer get the pane attached.

The attached pane did not follow these pickers. A picker runs inside QuickPane itself, and QuickPane does not watch its own windows for moves, so the pane on a picker stayed behind until a check that runs once a second caught up.

- The pickers list what the pane shows: each expanded group's visible tab, folders only, in the same order, at most 50.
- A pin on a drive or share that does not answer is left out. The picker waits at most 0.4 seconds in total for pins to answer, and a slow share holds up only its own pins.
- Other programs' Open and Save dialogs keep the pane, inside or beside, as before.

## Still open

- **#148 (QuickPane exits after an Explorer restart)** stays open until a desktop run restarts Explorer and QuickPane keeps running.
- **The pane still hides while you drag Explorer windows and other programs' dialogs.** That hide is deliberate. A pane beside a window would trail it by a frame. A pane inside a window would cover Explorer's own tree while Explorer lays it out again. A narrower hide for a beside pane, during a drag of the window's right edge, is a possible later change.
- **Testing.** This change was checked in Windows Sandbox, with both kinds of picker, moves and resizes, dead pins, and another program's Save dialog, and by unit tests. It has not yet run on a real desktop, and a network share that hangs rather than failing at once is covered by a unit test only.

## For developers

- `PickerPlaces` chooses the pins and checks them with `Directory.Exists`, one long-running task per drive or share. The first version used one thread-pool task per pin, and a two-core CI runner showed that hung checks could take every pool thread and starve a local pin.
- The checks ignore a pin's scan-time `IsFile` and `Exists`, because `IsFile` is a guess from the extension until the first probe, and would drop a folder named like `Site.v2`.
- `DialogPaneWatcher.IsOwnProcess` keeps the pane off this process's dialogs.
- The test suite has 868 tests, 17 more than 3.13.0.0.

## Install

Download `QuickPane-3.13.0.1-x64-setup.exe` and run it. It installs for the current user, with no administrator rights. Over an existing QuickPane, including one installed by the original project's installer, it closes QuickPane, replaces the program, and updates the same Add/Remove Programs entry. Your settings, groups, and pins in `%APPDATA%\QuickPane` stay where they are.

The zip holds the same program, for replacing the files by hand instead:

1. Close QuickPane, and wait for it to finish: `Start-Process "$env:LOCALAPPDATA\QuickPane\QuickPane.exe" -ArgumentList '--exit' -Wait`
2. Keep a copy of the current `QuickPane.exe` in `%LOCALAPPDATA%\QuickPane`, so you can go back.
3. Unzip the download, and copy `QuickPane.exe` and `QuickPane.exe.config` into `%LOCALAPPDATA%\QuickPane`, replacing the files there.
4. Start `%LOCALAPPDATA%\QuickPane\QuickPane.exe` again.

`SHA256SUMS.txt` lists the SHA-256 hash of the installer, the zip, and each file inside the zip. The files are not code-signed, so Windows SmartScreen may warn before the installer first runs. This release also carries a GitHub build provenance attestation, which `gh attestation verify <file> -R prisant-labs/windows-explorer-quickpane` checks.
