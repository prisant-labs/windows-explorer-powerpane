# Explorer PowerPane 4.0.0.0

QuickPane is now Explorer PowerPane. This release changes the name, the icon, and where the program and its data live, and nothing else. Because the name changes, it installs beside QuickPane rather than over it, so moving across takes a few manual steps, described below.

## Why the new name

This project began in October 2026 as a fork of [QuickPane by lso2](https://github.com/lso2/QuickPane) (PlexPixel), and every release from 3.10.0.2 to 3.13.0.1 was published as "QuickPane (fork)". It has since become a separate product, with its own releases, tests, and plans to publish in the Microsoft Store, so it needs a name of its own. The MIT license and its original copyright notice stay, and the About page still credits the original project.

## What changes

| Thing | Before | Now |
|---|---|---|
| Name in the Start menu, Add/Remove Programs, the installer, and About | QuickPane | Explorer PowerPane |
| Name in the pane header, the tray, and window titles | QuickPane | PowerPane |
| Icon | A star | A window with a lightning bolt in its side pane |
| Program | `%LOCALAPPDATA%\QuickPane\QuickPane.exe` | `%LOCALAPPDATA%\PowerPane\PowerPane.exe` |
| Settings, groups, and pins | `%APPDATA%\QuickPane` | `%APPDATA%\PowerPane` |
| Folder verb | Pin to Quick Pane | Pin to PowerPane |
| Release files | `QuickPane-<version>-x64-setup.exe` | `PowerPane-<version>-x64-setup.exe` |
| Repository | `prisant-labs/windows-explorer-quickpane` | `prisant-labs/windows-explorer-powerpane`; the old address redirects |

A pin's right-click menu item "Remove Shortcut" is now "Remove pin", the word the rest of the app uses.

## Moving from QuickPane

The two names are separate products to Windows, with their own program folders, data folders, and Add/Remove Programs entries. Both running at once would attach two panes to every Explorer window, so the PowerPane installer stops with a message while QuickPane is still installed.

1. **Back up your data.** Copy `%APPDATA%\QuickPane` somewhere safe.
2. **Uninstall QuickPane** from Settings, Apps. Uninstalling keeps `%APPDATA%\QuickPane`, so your groups, pins, and settings are still there.
3. **Install Explorer PowerPane.** On the installer's last page, untick "Launch Explorer PowerPane".
4. **Copy your data across.** In PowerShell, run `robocopy "$env:APPDATA\QuickPane" "$env:APPDATA\PowerPane" /E /XD "$env:APPDATA\QuickPane\Logs"`. This copies the folder's contents into the new data folder, which the installer has already created. It leaves the `Logs` folder behind, because the state files in it describe QuickPane's last run, not PowerPane's.
5. **Start Explorer PowerPane** from the Start menu, and check your groups, pins, profiles, and settings.
6. **Keep the old folder for a while.** Once PowerPane has worked for a week or so, `%APPDATA%\QuickPane` can be deleted.

If you already started PowerPane before step 4, exit it from the tray first, then copy and start it again.

Your copied settings still name the old folder, `%APPDATA%\QuickPane\Groups`. PowerPane reads any path inside the old data folder as the same place inside the new one, so the copied settings, and backups made by QuickPane, find your pins in `%APPDATA%\PowerPane`, and the copied `uistate.txt` keeps each group open or closed as it was. A groups folder you chose yourself, anywhere else, is left exactly as it is.

**Going back:** uninstall Explorer PowerPane, and install QuickPane 3.13.0.1 from its [release page](https://github.com/prisant-labs/windows-explorer-powerpane/releases/tag/v3.13.0.1). Its data folder is untouched.

## For QuickPane's update notice

QuickPane 3.x checks the old repository address for updates, and GitHub redirects that address to this one. So an installed QuickPane shows "QuickPane 4.0.0.0 is available", and its notice opens this page. Nothing updates by itself.

## For developers

- The namespace, assembly, source folder, test project, window class, mutex, exit signal, drag formats, and trace provider are all named PowerPane. The trace provider's GUID is derived from its name, so the recording profile in `scripts/trace/PowerPane.wprp` carries a new GUID.
- `Installer.iss` has a new `AppId` and two names: `MyAppName` ("Explorer PowerPane") for what people see, and `MyAppFolder` ("PowerPane") for where files go. Its `PrepareToInstall` stops while QuickPane's uninstall key or Run value exists, and the zip's `Install.ps1` does the same.
- `AppSettings.MapFormerDataPath` maps a `groupsPath` inside the old data folder, for the top level and every profile, whenever settings load or a backup is restored. `UiState.MapFormerKey` does the same for the group and tree keys in `uistate.txt`, which hold expanded folder paths.
- The update check now asks `prisant-labs/windows-explorer-powerpane` directly instead of relying on the redirect.
- The test suite has 891 tests, 23 more than 3.13.0.1.

## Install

Download `PowerPane-4.0.0.0-x64-setup.exe` and run it. It installs for the current user, with no administrator rights. If QuickPane is still installed, it stops and asks you to uninstall QuickPane first; see "Moving from QuickPane" above. Later PowerPane releases will install over this one and update the same Add/Remove Programs entry.

The zip holds the same program and its license, for replacing the files of an existing PowerPane install by hand. This is the first PowerPane release, so there is no such install yet: use the setup program. For a build from source, `Install.ps1` also stops while QuickPane is still installed.

`SHA256SUMS.txt` lists the SHA-256 hash of the installer, the zip, and each file inside the zip. The files are not code-signed, so Windows SmartScreen may warn before the installer first runs. This release also carries a GitHub build provenance attestation, which `gh attestation verify <file> -R prisant-labs/windows-explorer-powerpane` checks.
